# 与其让模型在数字奖励里瞎摸,不如让它读自己的错题本

**副标题**: GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning
**日期**: 2026-08-26
**来源**: https://arxiv.org/abs/2507.19457
**作者**: Lakshya A Agrawal, Shangyin Tan, Dilara Soylu, Noah Ziems, Rishi Kalra, Karel D'Oosterlinck, Krista Opsahl-Ong, Arnav Singhvi, Herumb Shandilya, Michael J Ryan, Meng Jiang, Christopher Potts, Koushik Sen, Alexandros G. Dimakis, Ion Stoica, Dan Klein, Matei Zaharia, Omar Khattab
**发表场所**: ICLR 2026 (Oral)

## 速读

GEPA 是一个针对复合 AI 系统的提示优化器。它替换掉强化学习(RL)中"标量奖励+梯度更新"这一整套机制,改用"读自然语言执行轨迹 + LLM 反思写新提示 + 沿 Pareto 前沿多样化保留候选"三步走。在四个任务四个模型上,它用**少 35 倍的 rollout** 超过 GRPO 平均 10%(最高 20%);也稳定超过当前最强提示优化器 MIPROv2 十几个百分点。

一句话:当你的系统能吐文字反馈时,让它自己写下一版提示,比让它去拟合一条稀疏奖励曲线更省钱、更快、也更强。

## 它到底在解决什么

**表面问题**: 把大模型适配到特定任务,现在主流有两条路。走 RL 路线(GRPO/PPO)需要数万到数十万次 rollout,烧钱且训练不稳;走提示优化路线(MIPROv2/TextGrad)则常常卡在局部最优,或需要人工调设计。

**真正的痛点**(作者看见了什么): RL 的核心浪费在于**信用分配的信号带宽**。策略梯度只能从一个标量奖励(对/错)里反推整条轨迹应当如何修改,信号极其稀疏;而现实里 LLM 系统运行时环境本身在**输出丰富的自然语言证据**——编译器错误、检索到的文档、评估器的解释、单元测试的失败原因。这些文字信号被 RL 主动丢弃了,只留下一个数字。

**GEPA 的转移**: 不再把"学习"看成参数梯度问题,而看成**在提示空间做进化搜索**,其中每一次"变异"由 LLM 反思上一批 rollout 的自然语言轨迹产生。奖励从"驱动梯度"变成"判定候选是否入池"。

形式化: 一个复合 AI 系统被写成 Φ = ⟨M, C, X, Y⟩,其中 M 是若干 LLM 模块、C 是控制流、X/Y 是输入输出空间。适配的对象是每个模块的**提示文本**,而不是模型权重。反馈函数 μ_f 除了返回标量,还返回一段**文本诊断**(执行轨迹 τ + 评估轨迹)。

## 它真正看见了什么

论文的核心洞察不是"用 LLM 优化提示"(这早有先例),而是三个耦合在一起的判断:

**判断一:文本反馈比标量反馈信息密度高一个数量级,且天然对齐到模块级。**
GRPO 面对一个"HotpotQA 最终答错"的信号,不知道该怪查询改写模块、还是检索模块、还是答案合成模块。而在 GEPA 里,反馈函数在每一跳独立报告"这一步缺少哪些文档",反思 LLM 因此能**指名道姓**地改写某个子模块的提示。这就是论文里反复出现的"隐式信用分配": credit assignment 不是靠优化算法算出来的,而是靠自然语言语义天然带出来的。

**判断二:贪婪爬山会掉进局部最优,Pareto 前沿是解药。**
朴素的进化循环倾向于总从当前最好的候选出发变异,结果所有子代继承同一个偏见,群体多样性坍缩。GEPA 的做法是:对训练集里每一条样本,记录"哪些候选在这条样本上分数最高";所有出现在**至少一个样本 top 层**的候选构成 Pareto 前沿,采样时按前沿加权。这样即使某个候选平均分不高,只要它在某类样本上独一无二地强,就会被继续繁殖。作者把这一策略比作 quality-diversity(Mouret & Clune 2015)的 illumination:目标不是找单点最优,而是**照亮解空间的多个山头**。

**判断三:反思式突变比"随机变异+选择"高效得多。**
经典 EvoPrompt 靠随机重写+锦标赛;GEPA 让 LLM 拿着 minibatch 的输入、输出、评估反馈,直接**写一段新的提示**。附录 C 的 Meta-Prompt 显示,反思器被要求"识别输入格式和任务描述、抽取利基事实性知识、总结可泛化策略、写进新指令"。这实际上把"梯度下降"替换成了"每一步都由 LLM 写一次课后总结"。

**贯穿证据**(锚点): HotpotQA 上 Qwen3-8B 配合 GEPA 用 **687 次 rollout** 达到的准确率,超过 GRPO 跑 **24000 次 rollout** 的结果。这是"35× 样本效率"数字的直接来源。附录里给出的候选演化树显示,一条从 candidate 0 到 candidate 11 的祖先链上,每次改动都能对应到一段具体的错误反馈(如"prompt 未强调保留原始查询实体")。

**边界与代价**(作者也承认的):
- Merge(系统感知交叉)在 GPT-4.1-Mini 上提升明显(+5%),但在 Qwen3-8B 上反而变差——超参(何时触发 merge、突变与交叉预算比)对模型很敏感。
- 反思器本身要跑 LLM,不是零成本;附录记录反思 LM 调用次数与优化 rollout 的比值。
- 推理时用作代码搜索工具(NPUEval/KernelBench)有前景但仍在早期。
- 未证明的场景:当反馈函数**无法**提供任何文字诊断(纯二分对错、无过程信号)时,GEPA 相对 RL 的优势会削弱到什么程度,论文没给出。

## 我能带走什么

**一个可迁移的判断框架**: 下次遇到"如何低成本把 LLM/Agent 系统适配到新任务"时,先问三个问题:
1. 我的环境**能否吐出结构化的文字反馈**(错误信息、验证轨迹、检索结果)?能——GEPA 类方法优先。
2. 我要优化的是**提示还是权重**? 复合系统里模块间边界清晰、可独立换提示——用 GEPA;需要改变模型内部表示——才动 RL/LoRA。
3. 我的候选池**多样性从哪里来**? 如果只维护 top-k,几乎必然陷入局部最优;Pareto 前沿或 MAP-Elites 是低成本的多样性来源。

**一条被 GEPA 强化的元规律**: 当你手里的信号从"数字"升级为"自然语言"时,应当同步升级你的**优化算法**——不是继续套用标量优化器,而是让 LLM 本身作为优化引擎读这个信号。这条规律以后判断任何"用 LLM 优化 X"的工作都适用:看它是否把 LLM 的语言理解能力真正用在了信用分配上,而不是仅仅当作生成器。

**一个能预测的推论**: 如果我把 GEPA 迁移到一个反馈函数极其贫瘠的任务(比如只有 0/1 且无解释),它相对 GRPO 的优势应该显著缩水;如果我把它迁移到反馈极丰富的任务(如代码优化,有编译器、profiler、单元测试三路信号),它相对 GRPO 的优势应该进一步扩大。这个预测本身可以用来判断未来的实证工作是否符合模型。

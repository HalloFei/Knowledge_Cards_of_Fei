# 别在门口丢掉“多大”和“多久”

**副标题**: Qwen2.5-VL Technical Report（动态分辨率与绝对时间编码，把定位和长视频理解放进同一个模型）

**日期**: 2026-10-20

**来源**: https://arxiv.org/abs/2502.13923

**作者**: Qwen Team, Alibaba Group

**发表场所**: arXiv preprint（2025-03）

---

## 速读

一张 4K 截图右上角有个十二三像素的关闭叉，人一眼看见。这类模型要说出它的坐标，在上一代基本做不到——难的不是看不懂界面。原来的管线要先把图缩到固定尺寸、再把坐标归一化，两步都很合理，用来解决“不同尺寸的图长得不一样”这个真问题。可那个叉缩完只剩三个像素，而这个模型的视觉侧一个词元对应图上 28×28 像素，三个像素的叉不再是一个形状，是某一块里的一点模糊；归一化再把“这块在原图里多大”抹掉。同一个模型家族，上一代在专业高分辨率界面榜 ScreenSpot Pro 上拿 1.6，这一代拿 43.6——二十七倍。这篇报告真正做的不是把模型变聪明，是把“多大”和“多久”这两个在门口被销毁的量重新留在模型算得到的地方：空间上不缩放、坐标写原图像素，时间上不数帧、编号对齐绝对秒。代价是这两个量只能精确到固定的颗粒，颗粒之内它能把东西指给你，颗粒之外（把任务做完）它没有多出任何东西。以后我看到某个系统在一个榜上突然好一大截，先不问“它是不是更强了”，先问：这个榜上要认的东西，在旧管线里是不是本来就在门口被销毁了。

## 它到底在解决什么

把那张截图放大看：右上角一个十二三像素的叉，人一眼就看见；模型要说出它的坐标，上一代基本做不到。原因不在“看不懂界面”。图被切成 14 像素的 patch，相邻四块再合成一个视觉词元（token），所以**一个词元对应图上 28×28 像素的一块**。那个叉原图 12 像素，缩到 1024 宽之后剩 3 像素——不到一块的百分之一。它在语言模型看到之前，就已经不是一个可以指的东西了。

归一化再把第二个量抹掉。模型输出 0.83，这是一个比例；它自己并不知道原图宽 3840，于是“这块在原图里有多大”变成一条必须被额外告知的外部知识。而在密集界面里这件事致命：一条 12 像素高的分割线和一个 120 像素高的按钮，归一化之后可以落在几乎同一个位置。

旧做法为什么曾经是对的？因为它解决了一个真问题：每张图尺寸不同，token 数就不同，训练没法打包；同一张图换个尺寸，坐标答案就变，监督信号自相矛盾。归一化和固定尺寸是把“尺寸”这个变量按住的标准手段。它只在一种情况下不要钱——目标够大、画面不密，那里本来也没什么可丢的。

所以卡点不在模型容量，在入口：**位置和量被当成了同一件事**。比例坐标保住了“在哪”（相对容器），丢掉了“多大”（绝对尺度）；固定尺寸保住了“序列长度可控”，丢掉了“够不够看清”。这两个损失只在界面截图、整页文档、远处小目标这类地方现形。这篇要处理的就是这类地方。

## 它真正看见了什么

一句话：这一代不是把模型变聪明，是把这两个被销毁的量重新留在模型算得到的地方；而量一旦留下，它能精确到哪里就由一个颗粒决定——颗粒之内是指认，颗粒之外还是操作。

先补空间那一半。“原生分辨率”不是“喂更大的图”，是**图的尺寸不再被改写成常数**：高宽取 28 的倍数，原样切块，图越大 token 越多（一张 4K 截图会变成一万多个视觉词元，这是我从“一词元 28 像素”算的，论文没给这个数）。“绝对坐标”也不是换一种写法：框和点直接用原图的像素值写，0.83 变成 x=3187，数字本身就带着尺度，模型不必先被告知原图多宽。区别在这里——归一化坐标是相对容器的，容器一变，同一个数字指的东西就变；绝对坐标是相对世界的。

文档那条线把这件事推到了底：整页被序列化成一棵 HTML 树，每个段落、表格、图表、公式都带一个 data-bbox，坐标和文字挤在同一个序列里。这时绝对坐标不只是一个编码约定，它成了监督信号本身——模型要同时吐出内容和内容所在的那块像素。它在这一类任务上领先的幅度，是全部榜里最大的那一档——当然不是全胜，整页文档转写的编辑距离上，中文这一路它仍落后 Gemini 一截。而这类任务恰好是信息密度最高、最容易被缩放压碎的那一类：同一条因果，换了个场景又出现一次。

代价也立刻出现：token 数正比于面积，所以“看得清”等于“序列变长”等于“更贵”。ViT 里的应对是窗口注意力：32 层里只有 4 层做全图注意力，其余在 112×112（也就是 8×8 个 patch）的窗口内做，代价从 patch 数的平方降成线性。这不是“更快的注意力”，是**让保留分辨率这件事付得起**。这一句是作者的解释（他们说降低了开销），论文全篇没有消融去隔离它。

代价的另一半是颗粒。四块 patch 合成一个词元，意味着 28 像素以下的位置细节在表示里根本不存在。这解释了一个论文自己没解释的现象：它把点定位列为主打能力，但这一项没赢过 Molmo（表 6 里 67.5 对 69.2）。框可以粗，点不能粗——框错 20 像素还是对的，点错 20 像素就是错的。（这一层是我的读法，论文只给了分数。）

时间上是同一个病的第二次发作。MRoPE 把位置拆成时间、高、宽三份；上一代里时间那一份的编号是**第几帧**。固定采样率下这没问题，但这一代训练时故意让采样率变动，于是同一个 3 秒的动作，30fps 采是第 90 到 180 帧，1fps 采是第 3 到 6 帧——编号完全不同，“多久”在表示里消失了，只剩“排第几”。改法是把时间编号对齐到绝对秒，于是**编号之间的差就是秒数**，节奏和间隔成了模型能直接算的量。区别与空间那一半完全同构：帧序号是索引，秒是量。

这条也顺带解释了“小时级视频”怎么成为可能。评测时帧数上限 768、视频 token 上限两万四，一小时的片子摊下来是几秒一帧——它没有看得更密，它是**把时间轴变成了一个可相减的坐标**，所以稀疏采样下仍答得出“第几分几秒”（秒级不来自帧的密度，来自时间轴自带单位，加上训练数据里时间戳写成秒和时分秒帧两种格式；后半句是我的推演）。这一半的成绩是 Charades-STA 事件定位 mIoU 50.9，GPT-4o 是 35.7，自家上一代 43.6。它改变的不是“视频问答更准”，而是“稀疏采样下，边界时刻变成一个算得出来的数，而不是猜得出来的词”。

```text
一张 4K 截图：12px 的关闭叉
  旧  缩到 1024        -> 叉剩 3px，糊进邻居
      坐标写 0~1       -> "0.83" 不含尺度
  新  按 28 倍数原样切  -> 一个词元 = 28x28 像素
      坐标写原图像素    -> 数字自带尺度
        |
        +-> 可指认：ScreenSpot Pro 1.6 -> 43.6
        +-> 到颗粒为止：点定位 67.5 < Molmo 69.2

一小时视频：帧数上限 768
  旧  时间是帧号       -> 1fps 与 30fps 编号不同
  新  时间对齐绝对秒    -> 编号之差就是秒
        |
        +-> 稀疏采样下仍答得出"第几分几秒"
```

指认一旦成为原语，别的能力就长在它上面。计数那一项它也是领先的，但靠的是一个“先检测再数”的提示——计数被拆成了指认加算术，而不是一种独立的数感。这反过来标定了颗粒的位置：能拆成指认的能力它就有，拆不成的，颗粒帮不上忙。

最有用的一处对照，是这条杠杆该失效的地方。在普通的指代理解榜上（RefCOCO 那一组），它反而略低于上一代开源最强的对手；开放词表检测上也还差专用模型一截。这两个场景目标都够大、图都不算密，门口本来没丢东西，杠杆没有可回收的损失，也就没有收益。所以那二十七倍不能读成“全面更强”，它是“补回来”。这条对照排除了“新一代什么都更好”这个解释——如果只是模型更大更强，那两个榜也该一起涨。

再动一个条件：把管线重新缩回固定尺寸，绝对坐标留着也没用，因为像素已经糊了。按这个模型，最先变的不是通用 VQA，而是“目标只占几十像素”的那些任务——小图标点击、密集表格的单元格、远处的小目标；而且失败方式不是“答错”，是“答得理直气壮却落在隔壁”，因为那块区域在表示里被邻居吃掉了。反过来，只把坐标从像素改回比例、分辨率不动，最先变的是数值精度：它还能说“右上角那块”，但给出的坐标会系统性偏移，偏的方向随图片尺寸变。这两个预测论文都没做实验。

分寸得说清。全文没有一处消融：ViT 是从头训的，数据从 1.2T token 涨到 4.1T，坐标、时间编码、分辨率同时换，所以“二十七倍是保留尺度带来的”是我的结构推演，不是为了证明而被隔离出来的因果。1.6 这个数也不能读成“上一代看不见按钮”：ScreenSpot Pro 是后来发布的专业高分辨率榜，对上一代本来就在分布外，1.6 接近瞎猜，而不是“试过但失败了”。还有一层边界是这张表自己给的：指认全面领先，整机任务却没领先——OSWorld 上它落后于 Claude，AndroidWorld 上和 GPT-4o 打平。**一个坐标对了，不等于下一个动作对**——它能把那个叉指出来，却不知道点下去之后界面会变成什么样。这一层不是颗粒能解释的，是指认和操作本来就不是一件事。

## 我能带走什么

一条规则：以后看到某个系统在一个榜上突然好了一大截，先不问“它是不是更强了”，先问——**这个榜上要认的东西，在旧管线里是不是本来就在门口被销毁了？** 如果是，那一大截是补回来的，不是多出来的；补回来的东西不会溢到别的能力上去。

两个用法。调自己的管线时，先量一件事：一张典型输入里最小的那个必须认出的东西占多少像素，除以你的颗粒（patch 尺寸乘合并倍数），如果不到一格，先改输入，别先换模型。看时间相关的任务时，先问时间是怎么进模型的：帧号、文本时间戳，还是一个能相减的数。前两种下“节奏”和“间隔”根本没有表示，再多视频数据也补不上这个洞。

最后诚实交代分量：这是技术报告，没有消融，它给的是“这一代在哪些榜上把丢掉的东西补回来了”的横截面，不是“为什么”的因果链。

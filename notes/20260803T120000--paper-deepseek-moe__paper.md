# 让每个专家真正只学一件事，靠的是把专家切碎再隔离出公共部分

**副标题**: DeepSeekMoE: Towards Ultimate Expert Specialization in Mixture-of-Experts Language Models

**日期**: 2024-01-11

**来源**: https://arxiv.org/abs/2401.06066

**作者**: Damai Dai, Chengqi Deng, Chenggang Zhao, R.X. Xu, Huazuo Gao, Deli Chen, Jiashi Li, Wangding Zeng, Xingkai Yu, Y. Wu, Zhenda Xie, Y.K. Li, Panpan Huang, Fuli Luo, Chong Ruan, Zhifang Sui, Wenfeng Liang

**发表场所**: arXiv preprint, 2024

## 速读

传统 MoE（如 GShard）想省算力：一层里放 N 个专家，每个 token 只激活 top-K 个，于是参数很多但每步只算一小部分。问题是——花了这么多参数，模型却没变得更聪明，因为专家没能各管一摊。这里缺的关键概念不是"专家数量"，而是"专家专业化"：每个专家是否真的学到了互不重叠、各有侧重的知识。论文发现专业化被两件事破坏——**知识混杂**（专家太少太大，被迫什么都学）和**知识冗余**（不同专家重复学同一批公共知识）。DeepSeekMoE 用两招对症：把每个专家切成更细的小专家、再从选择池里激活更多个（缓解混杂、给组合更多自由度），并单独隔离几个"共享专家"永远激活来承包公共知识（缓解冗余）。结果是同等算力下专业化程度和性能都明显更高。以后再看到"MoE 参数很大但收益不明显"，先别归咎于规模，而要问：专家是不是被逼着一专多能、又在重复劳动？

## 它到底在解决什么

一个具体的反常现象贯穿全文：MoE 明明把参数量堆到很大，激活的算力却只是其中一小块，理论上"便宜地变大"，可实测里专家们的表现却像一群没分工的通才——你分析激活模式会看到，很多专家在处理五花八门的输入，彼此还高度重叠。参数涨了，专业化没涨。

人们原来怎么处理？沿用 GShard 式的标准配方：一层里放 N=16 个专家，每个 token 走门控网络挑出得分最高的 top-2 个来算。这套做法默认"专家多 + 每个专家大 = 能力强"。它没有单独盯住一个关键区分：**"有很多专家"不等于"每个专家专精一类知识"**。当每个专家块很大、可选组合又很有限（16 里挑 2），两件坏事同时发生：其一，专家太粗，一个专家不得不同时承接差异很大的输入，被迫成为通才（知识混杂）；其二，很多 token 都需要一些通用的、基础的公共知识，于是每个被选中的专家都得各自把这份公共知识再学一遍（知识冗余）。两者都在稀释专业化。到这里，读者自然会期待：能不能让专家"分得更细、又不必重复学公共知识"？

## 它真正看见了什么

新判断一句话：专业化不是靠堆专家数量得到的，而是靠**提高专家组合的自由度**加上**把公共知识从路由专家里抽离**共同得到的。

先看第一个承重概念——**细粒度专家分割（fine-grained expert segmentation）**。它区分的不是"专家多少"，而是"专家多细、组合多自由"。做法是把每个原始专家沿中间维度切成 m 份小专家（FFN 中间隐层缩到 1/m），专家总数从 N 变成 mN；为保持每步算力不变，激活数也从 K 提到 mK。关键不在参数，而在**组合空间的爆炸式扩大**：原来 16 选 2 只有 120 种组合，切成 64 选 8 后组合数达到约 44 亿。为什么这能提升专业化？因为门控现在可以为不同类型的输入拼出高度差异化的专家子集，每个小专家只需覆盖更窄的知识面，不再被迫一专多能——直接对治了前面的"知识混杂"。

再看第二个承重概念——**共享专家隔离（shared expert isolation）**。它区分的是"公共知识"与"专属知识"。做法是从池子里固定拿出 K_s 个专家当**共享专家**，对每个 token **永远激活**、不参与路由竞争；剩下的路由专家里，每个 token 再挑 mK−K_s 个。为什么这能提升专业化？因为公共的、跨领域都要用的基础知识被集中压进了共享专家，路由专家就不必人手一份地重复学它——直接对治了前面的"知识冗余"。省下的容量可以用来学各自真正专属的东西。

把两个概念接成一个最小解释模型：

```text
输入 token
   │
   ├─► 共享专家 K_s（恒定激活）───► 承包公共知识，消除冗余
   │
   └─► 门控在 mN−K_s 个细粒度路由专家中挑 mK−K_s 个
          │  (组合自由度极大 ↑)
          ▼
       每个小专家只覆盖窄知识面 ──► 消除混杂
                    │
                    ▼
   两路输出相加 ──► 同等算力下专业化 ↑ ──► 同参数/算力性能更强
```

模型怎样解释开头那个"参数大但专业化差"的锚点？因为旧配方同时踩了混杂和冗余两个坑，参数被浪费在"重复学公共知识"和"通才式覆盖"上。DeepSeekMoE 把这两处浪费各自堵住，专业化就随之上来了。

换一个邻近情况来区分：如果只做细粒度分割、不做共享隔离，会怎样？模型预测——混杂缓解了，但公共知识仍被众多路由专家重复学习，冗余依旧拖累专业化。反过来只隔离共享专家、不细分，则组合自由度不足，专家仍偏通才。论文的消融正是这个方向：两招都要，缺一效果都打折。

改变一个条件的方向性预测：如果你**关掉表现最好的那个路由专家**，专业化程度越高的模型应该掉得越狠（因为知识不可替代、不冗余）。论文正是用这个"禁用 top routed expert 后性能下降更多"的现象，反向证明 DeepSeekMoE 的专家更专精、更不可相互替代。同理，减少共享专家数量、或把激活专家换成随机而非门控挑选，性能都会明显下降——说明这两个机制确实在承重。

证据（紧贴主张）：
- **2B 规模**：DeepSeekMoE 2B 匹敌拥有约 1.5 倍专家参数与算力的 GShard 2.9B；并逼近相同总参数的稠密模型上限——说明它把 MoE 的效率天花板往稠密模型方向抬高了。
- **16B 规模**：与 LLaMA2 7B 性能相当，却只用约 40% 的算力。
- **145B 初步扩展**：持续优于 GShard，性能接近 DeepSeek 67B，仅用约 28.5%（激进设置下 18.2%）的算力。
- **专业化直接证据**：禁用 top routed expert 时性能下降幅度大于 GShard；共享专家不可被路由专家替代——这些是最能改变判断的结果，其余多为规模化的印证而非新机制。

适用边界：以上主要在 2B/16B/145B 语言建模与常规基准上验证，"专业化更高"是通过激活模式分析与消融**间接**推断的（作者解释 + 结构消融），并非对每个专家学到什么知识的直接标注；跨任务、超大规模下的稳健性属于初步验证。

## 我能带走什么

一条可复用的判断规则：**以后看到"MoE 参数规模很大但收益不成比例"，先别急着归因于规模不够或数据不够，而先问两件事——专家是不是太粗被迫当通才（知识混杂）？公共知识是不是被每个专家重复学了一遍（知识冗余）？** 这两个问题指向的是"专家组合自由度"和"公共知识是否被隔离"，往往比继续堆参数更能解释性能停滞。

两个真正相关的用法：
- 设计或调 MoE 时，把"专家粒度 + 激活组合数"和"是否设共享/常驻专家"当成两个独立旋钮分别调，而不是只调专家总数。
- 评估一个 MoE 是否真的专业化，用"禁用最强专家看掉多少分"这把尺子——掉得越多，专家越不可替代、越专精。

若你的场景本就没有大量跨输入的公共知识，共享专家的收益会缩水——这时它更像一把"识别冗余问题"的诊断尺，而非必用的部件。

# 让语言模型在心里先走一遍再答

**副标题**: Reasoning with Language Model is Planning with World Model (RAP)

**日期**: 2026-08-25

**来源**: https://arxiv.org/abs/2305.14992

**作者**: Shibo Hao, Yi Gu, Haodi Ma, Joshua Jiahua Hong, Zhen Wang, Daisy Zhe Wang, Zhiting Hu

**发表场所**: EMNLP 2023

---

## 速读

CoT 让 LLM 把推理写成一条动作链，但链上没有"世界现在是什么样"，一步走错就只能硬着头皮往下走。RAP 让同一个 LLM 换个 prompt 就兼任两个角色：一个作为 agent 提议下一步动作，另一个作为 world model 预测这个动作会把状态变成什么样；再套一层 MCTS 用四种可选的 reward 打分、回溯、扩展。这多出来的一个概念——"显式的中间状态"——让 LLaMA-33B 在 Blocksworld 6 步任务上把 CoT+GPT-4 反超 33%。以后看到"LLM 推理失败"，先别急着换更大模型或更花的 prompt，而先问：它在推理途中有没有一个可以查询、可以回退的状态？

## 它到底在解决什么

一个具体的失败：Blocksworld 里给出初始布局和目标（红块在蓝块上、橙块在红块上）。CoT 让 LLM 一口气写出四步：拿橙、放红上、拿黄、放蓝上——第一步就把橙块摞到红块上了，可这时红块还没上蓝块，于是永远达不成目标。GPT-3 在这类任务上成功率 1%，人类 78%。

问题不是模型"不懂积木"，而是它推理时脑子里没有一个可以查询的现场。CoT 生成的是 `(a₀, a₁, a₂, ...)` 这样的纯动作序列，中间没有"执行完 a₀ 之后世界变成什么样"这个中间产物。于是 LLM 既不知道下一步的动作是否合法，也没法在发现走错时退回去换一条路——因为根本没有"这里"可以退回。

以往的补救方式各有短处。Self-Consistency 采样多条链投票，只是把同一种短视重复很多遍；Least-to-Most 一次性把子问题全拆出来，拆错了也不改；LLM+P 让 LLM 翻译成 PDDL 再喂经典规划器，但一离开积木、机械臂这类可形式化的领域就用不了。到这里读者应该开始想：能不能让 LLM 自己在心里维护一个状态，一边走一边看着改？

## 它真正看见了什么

RAP 的判断是：**推理不是生成一条链，而是在一棵可以回溯的树上做规划；而这棵树的世界模型可以从同一个 LLM 里 prompt 出来**。这一句里的每个词都是承重的，下面一个个让它落地。

**状态 vs. 动作**是这篇最基础的区分。CoT 里"pickup red block"是一个动作，然后紧跟着下一个动作——中间没有状态。RAP 里每走一步都强制生成 sₜ：Blocksworld 中 sₜ 是当前所有积木的位置和手是否为空（用自然语言写出），GSM8K 中 sₜ 是"目前已知的中间变量值"，PrOntoQA 中 sₜ 是"当前正在盯的那条事实"。有了 sₜ，"下一步动作是否合法"、"离目标还差多少"这些问题才有对象可问。

**world model** 是一个映射 p(sₜ₊₁ | sₜ, aₜ)：给我当前状态和一个动作，还给我下一个状态。它不是"知识库"，也不是"记忆"，而是一步预测。RAP 的关键操作是——用同一个 LLM，换一个 prompt，就让它扮演这个映射。Blocksworld 里问它"手拿着红块的时候执行 stack on blue，现在积木和手的状态是什么？"，它就吐出新的自然语言状态。这里的区别是：agent 侧问"下一步做什么"（p(a|s)），world model 侧问"做完后世界什么样"（p(s'|s,a)），是两个独立的推断，只是碰巧共享同一份参数。

**MCTS** 让这两件事在一棵树上组织起来。每个节点是一个状态，每条边是一个动作。四个阶段循环：选择（Selection，用 UCT 公式 `Q(s,a) + w·√(ln N(s)/N(c(s,a)))` 在 Q 值和探索项之间做权衡，走到叶节点）→ 扩展（Expansion，agent 采 d 个候选动作，world model 分别预测 d 个新状态，接成 d 个子节点）→ 模拟（Simulation，用轻量 reward 快速 roll-out 到终止状态，估个 Q）→ 回传（Back-propagation，把这条路径上收到的 reward 沿路更新每个 Q(s,a)）。回传是回溯能力的技术出处：一次失败的 roll-out 会把它前几步的 Q 拉低，下一轮 Selection 自然就会去试别的分支。

**reward** 是打分权。RAP 提供了四种可插拔的口味：动作的 log-prob（LLM 觉得这一步"顺不顺"）、状态的 self-consistency（多次采样，看主流答案占比，越集中说明世界模型越确信）、self-evaluation（直接问 LLM "Is this reasoning step correct?"，取 "Yes" 这个 token 的概率）、任务启发式（Blocksworld 里数一下当前状态满足了几个目标条件）。不同任务挑不同组合。

把这五样东西接起来，就是下面这个最小模型：

```text
sₜ  ──(agent LLM 提议 d 个动作)──▶  {aₜ⁽¹⁾, ..., aₜ⁽ᵈ⁾}
                                        │
                                        ▼
               (world model LLM 各预测下一状态)
                                        │
                                        ▼
                            {sₜ₊₁⁽¹⁾, ..., sₜ₊₁⁽ᵈ⁾}
                                        │
                                (每一步给 rₜ)
                                       │
                                        ▼
                    MCTS: Select ▸ Expand ▸ Simulate ▸ Backprop
                                        │
                                        ▼
                         挑一条累积 reward 最高的路径
```

回到 Blocksworld 那个失败锚点，模型是这样解释的：CoT 头两步就摆错也没办法（没有 sₜ，看不出"红还没上蓝"这个前提被破坏了）。RAP 头两步同样会犯错，但——(1) 每步之后 world model 都生成新的状态描述，agent 在下一轮 Selection 时能"看见"当前布局和目标的差距（这就是 r₂）；(2) 一条错误路径 roll-out 完发现拿不到大 reward，Backprop 把这个坏消息回传到根节点附近，UCT 下一轮就倾向去试没走过的分支；(3) 计算 rₜ 时只喂当前状态而不喂历史，等于把每步都当成一个新的短任务，把长任务的复杂度摊薄到每个决策点。这三条合起来才是"回溯"的真正机制——不是模型突然会"反悔"，而是搜索算法把不同分支的价值实测出来了。

**一个邻近情况**能让区别更清楚：Yao et al. (ToT, 2023) 用 BFS/DFS 在 LLM 生成的思维步骤间搜索，看起来结构相似。差别在——ToT 的"节点"仍是思维片段，没有把状态和动作分开，也没有独立的 world model 去预测转移；本质上它是"多条 CoT 之间做择优"，而 RAP 是"在真正的 MDP 上跑规划"。这也是为什么 ToT 在需要维护复杂中间状态的 Blocksworld 上不如 RAP 明显。

**一个条件变化**能预测模型什么时候会失灵：如果 world model 那部分很不准会怎样？比如任务的状态难以用自然语言精确描述（例如涉及连续物理量、精细几何、长期时序耦合），world model 的 p(s'|s,a) 就会漂移，MCTS 的 roll-out 越深，估出的 Q 值越不可信，规划反而会稳定地选到糟糕分支——这时候 RAP 会比 CoT 更差（因为 CoT 至少不会自信地深挖错误分支）。作者在文中承认 RAP 在需要外部环境交互的开放世界任务上边界模糊，这条预测和作者的自陈相符。

**证据分寸**要贴着主张：
- Blocksworld 2/4/6 步任务：CoT (LLaMA-33B) 分别 17%/2%/0%，RAP 到达 100%/88%/42%，且以 33% 相对优势反超 CoT+GPT-4。这一条较稳地显示了 world model + MCTS 在**离散、可形式化、状态可用自然语言穷举**的规划任务上的价值。
- GSM8K 数学题：RAP 48.6%（+aggregation 51.6%）对 CoT+SC 46.8%——只在这些条件下显示了微弱优势，且提升的一大部分来自 aggregation 这种和 SC 同质的操作。**这条不能被解读为 "RAP 让 LLM 更会数学"**，只能说 sub-question 分解在有 reward 引导时略优于无引导的一次性分解。
- PrOntoQA 逻辑推理：证明准确率从 64.8% 到 78.8% 是较明显的提升，但 PrOntoQA 本身是合成数据集、规则封闭，提示 RAP 在**规则集有限、每步只做一跳推理**的场合有效，不等于它掌握了一般的一阶推理。

论文没有直接测的，作为结构推演补上：Q 值回传等于把"未来奖励"折现到当前决策，UCT 的探索项等于把"没试过"这件事本身作为一种价值——所以 RAP 优势最明显的场景是"每一步的正确性很难当场判断，但走到底容易判断对错"（Blocksworld 目标达成、逻辑证明结束）；反过来，若终局奖励也很稀疏或很嘈杂（如开放式生成任务），MCTS 的四阶段本身也会退化。

## 我能带走什么

以后看到 LLM 推理任务失败，先不急着判断"模型太小"或"prompt 不够精"，而先问：**这条推理链里有没有一个显式的中间状态，让下一步的合法性和距离目标的远近可以被查询？** 若没有，加world model + 一层搜索通常比换更大模型收益大得多。

一个真正相关的用法：当你在做 agent 类应用时，把"生成动作"和"预测动作结果"分开成两个 LLM 调用（哪怕是同一模型的两次不同 prompt），只这一步就能显著改善多步任务的稳定性——因为你从此有了一个可以打分、可以回退的对象。反之，若任务的世界状态天然无法用自然语言写清楚（比如涉及精细感知或连续控制），这套框架不会自动生效，得先想清楚 sₜ 到底是什么，否则 world model 那一环会稳定地骗你。

与本笔记库中的 STRIPS 局限对照：RAP 恰好回应了 STRIPS 局限 2（缺显式世界模型——RAP 用 LLM prompt 出一个）、局限 4（缺规划-执行分离——RAP 在心里 roll-out）、局限 6（缺搜索启发式——RAP 用 self-eval / confidence / log-prob 当 heuristic）。它没有解决的是 STRIPS 局限 1（谓词符号化）和局限 5（终身学习）——RAP 的每次规划仍是一次性的、无记忆的。

# 让状态自己决定记谁忘谁,才追平了注意力

**副标题**: Mamba: Linear-Time Sequence Modeling with Selective State Spaces

**日期**: 2026-08-13

**来源**: https://arxiv.org/abs/2312.00752

**作者**: Albert Gu, Tri Dao

**发表场所**: arXiv 预印本 / 2023（v2 2024）

---

## 速读

有一类模型（状态空间模型，SSM）在超长序列上又快又省，却在语言这种信息密集的离散数据上一直打不过注意力。作者发现症结不是模型太小，而是它的"内部状态"用一套**对所有 token 一视同仁的固定规则**在压缩历史——它能按位置记事，却不能按内容判断"这个词值得记、那个词该扔"。Mamba 让决定"记还是忘"的那几个参数变成**当前输入的函数**（选择机制），状态就能根据内容动态开合；代价是不能再用卷积快速算，于是作者又用一个贴着 GPU 显存层级设计的扫描算法把速度补回来。结果：第一次有线性时间模型在语言上追平强 Transformer 配方，还能把训练时见过的长度外推 4000 倍。以后再看到"某高效模型在长文本上不升反降",我不会先怪它容量不够,而会先问:它的状态能不能按内容选择性地丢掉噪声。

## 它到底在解决什么

先看一个具体的失败。给模型一串 token,中间夹着随机数量的无关噪声（比如口语里的"呃""那个"),要求它只把有颜色的关键 token 按顺序复制出来——这叫**选择性复制**任务。老一类高效模型在这里栽了:把普通复制任务（关键 token 间隔固定）做得很好的同一个模型,一旦间隔变成随机的,准确率就崩了（S4 只有 18%）。

要理解为什么栽,得先看这些模型省钱省在哪。注意力之所以又强又贵,是因为它**根本不压缩**:推理时要把整段上下文（KV 缓存）原样存着,所以慢、且随长度平方增长。反过来,循环类模型（包括 SSM）只维护一个**固定大小的状态**,推理每步都是常数时间——省就省在这个"把上下文压进一个小状态"上。那效果的上限,就取决于这个状态压缩得好不好。

关键的旧假设藏在这里:此前所有能高效计算的 SSM 都是**线性时不变**的（LTI）——决定状态怎么更新、怎么读出的那套参数,对每个时刻、每个 token 都一模一样,横竖不变。这套"不变"正是它能改写成卷积、从而快速并行训练的前提。但代价是:状态的更新规则不看当前 token 是什么。于是它可以精确按"第几步"记事(时间感知),却无法按"这个词是不是关键"来决定记或忘(内容感知)。随机间隔一来,静态规则对不上,任务就做不了。到这一步,我们该期待的新答案已经很清楚:能不能让状态的开合,由它正在读的那个 token 说了算。

## 它真正看见了什么

一句话:**把决定信息如何沿序列传播的那几个参数,从"对所有输入固定"改成"随每个输入变化",状态就获得了按内容选择的能力——这才是追平注意力的关键,不是把模型堆大。**

先把"状态"这个承重概念说清。SSM 给每个通道维护一个隐藏状态 h,像一个不断被改写的记忆槽:每来一个输入 x,状态按 `h_t = A·h_{t-1} + B·x_t` 更新,再按 `y_t = C·h_t` 读出。A 管"上一刻的记忆保留多少",B 管"当前输入写进去多少",C 管"从记忆里读出多少给输出"。在旧 LTI 模型里,A、B、C 以及那个控制离散化步长的 Δ 全是固定常数——记忆的开合阀门被焊死了。

Mamba 的动作就一处:让 **B、C、Δ 变成输入 x 的函数**(通过一个线性投影现算)。这样每个 token 都能带来一套不同的阀门开度。其中最关键的是 **Δ(离散化步长)**。Δ 可以理解成"这一刻要不要把记忆清空、全神贯注在当前输入上"的旋钮:Δ 变大→重置旧状态、聚焦当前 token(相当于"选中"它);Δ 变小→当前输入被当成瞬时噪声、几乎不改写记忆(相当于"忽略"它)。作者证明,当把状态维度缩到最简(N=1),这套机制恰好退化成经典 RNN 的门控 `h_t = (1−g_t)h_{t−1} + g_t·x_t`——门控值 g_t 由输入算出。也就是说,**RNN 的门控只是这个选择机制的一个特例**;而选择机制反过来给了它一个更普适的解释:门控本质是"按内容离散化"。这解释了选择性复制任务里发生了什么——遇到噪声 token,模型让 Δ→0(门关上)直接跳过它;遇到关键 token,让 Δ→大(门打开)写进状态。静态卷积核做不到这种随内容变化的开合。

但这一改动立刻撞上一堵墙,这是理解 Mamba 为何是"硬件感知"的核心。参数一旦随输入变化,模型就从时不变变成**时变**,而时变就**不能再改写成卷积**——卷积并行正是旧 SSM 快速训练的唯一依仗。退回到逐步循环,又有两个麻烦:循环天生是串行的;以及要把展开后的大状态(形状 B×L×D×N,比输入大 N≈10~100 倍)物化在显存里,慢得离谱。作者的解法是把它当成一个**显存带宽问题**而非算力问题来治:不在慢速显存(HBM)里物化大状态,而是把参数从 HBM 搬进快速片上缓存(SRAM),在 SRAM 里完成离散化和递推,只把小的输出写回;串行用**并行扫描**算法绕过;反向传播需要的中间状态不存、而是重算(重计算)。三招合起来,时变模型也能算得比旧卷积 SSM 还快(A100 上约 3 倍),显存占用与 FlashAttention 相当。

把这些概念接成一个最小模型:

```text
当前 token 内容
   │  经线性投影现算
   ▼
Δ / B / C 随输入变化(选择机制)
   │
   ▼
状态 h 按内容开合:关键则写入、噪声则跳过
   │  时变 → 不能卷积
   ▼
硬件感知扫描(SRAM 内递推 + 并行扫描 + 重算)
   │
   ▼
状态只保留相关信息 → 长上下文不被噪声淹没
   │
   ▼
选择性复制/归纳头做对;语言上追平 Transformer;长度可外推
```

**回到原锚点**:选择性复制任务上,只把内层从 S4 换成带选择的 S6,准确率从 18% 跳到 97%+;而单纯给架构加乘性门控(H3、Hyena)只是部分改善——作者据此论证,**沿序列轴按内容选择**才是关键,架构门控不是选择机制的替代品。

**区分一个邻近情况**:普通复制任务(间隔固定)里,LTI 模型和 Mamba 都能做对,因为只需"按第几步记事"的时间感知。模型据此预测:只有当任务要求随内容变化的间隔或过滤时,选择机制才拉开差距——这正是它在离散语言、DNA 上强、而在某些连续感知模态上优势没那么大的方向。

**改变一个条件**:如果去掉选择性(退回 LTI),模型首先失去的就是"按需清空状态"的能力——于是上下文越长,固定卷积核聚合进来的噪声越多,性能不升反降。这在 DNA 实验里直接观察到:HyenaDNA(LTI)随序列变长反而变差,而 Mamba 一路到 100 万长度仍持续变好(较稳地显示,跨模型且有 LTI 对照)。归纳头任务上,Mamba 在训练长度 256 上学会后,能外推到 100 万(约 4000 倍),而其它方法都过不了 2 倍(在这些合成任务条件下显示)。语言建模上,Mamba 是第一个在标准 scaling law 下追平强"Transformer++"配方的免注意力模型,3B 规模的下游质量匹敌两倍大的 Transformer(在 ≤1.4B 训练规模、Pile 数据集条件下显示)。

需要分清分量:选择机制"追平注意力"这条主张,证据来自语言/DNA/音频三模态、且有 LTI 基线对照,较稳;但"A 也做成可选会有类似效果"只是作者的假设(为简化没做),属未验证推测;"复数还是实数更好"也停在经验观察,作者只给了"连续模态偏复数、离散模态偏实数"的猜想。

## 我能带走什么

以后看到某个"高效/线性"序列模型在长文本上**不升反降**或做不了按内容检索的任务,我不会先归因于"状态容量不够、再堆大点",而会先问:**它的状态更新规则是不是时不变的?它能不能根据当前输入决定丢掉什么、记住什么?** 能不能按内容选择,往往比状态多大更决定成败。

一个可迁移的判断:当你需要模型"按内容过滤噪声、在边界处重置记忆"(比如拼接多文档、RL 的 episode 边界),时不变模型天然会串味,而带选择/门控的循环状态可以在边界让 Δ→∞ 清空——这是选型时值得先确认的一条性质,而不是等训练完再补救。

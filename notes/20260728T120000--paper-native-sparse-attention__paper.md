# 稀疏注意力可以不牺牲性能，前提是硬件对齐加原生训练

**副标题**: Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention（原生稀疏注意力：硬件对齐且原生可训练的稀疏注意力机制）

**日期**: 2026-07-28

**来源**: https://arxiv.org/abs/2502.11089

**作者**: DeepSeek-AI 团队

**发表场所**: arXiv 2025

---

## 速读

标准注意力在长上下文建模时计算成本随序列长度二次增长，现有稀疏注意力方法要么推理时才压缩（无法学习最优模式），要么启发式选择（召回率低），要么动态聚类（硬件不友好），没有一个能做到「训练和推理全程稀疏且性能不降」。这篇论文发现：注意力分数天然呈现块状聚集，相邻 token 常有相似的注意力权重——只要把稀疏设计成「压缩块 + 选择块 + 滑动窗口」三层，并让选择操作在 GQA 组内共享索引，就能既减少内存访问又保留关键信息。结果是：27B 参数模型预训练后，在通用、长上下文和推理任务上达到或超越 Full Attention，64k 序列解码加速 11.6 倍。以后做长上下文模型，不要只看稀疏比例，先问「这个稀疏设计能不能端到端训练」和「它的内存访问是否块对齐」。

## 它到底在解决什么

一个 64k 长度的序列，标准注意力要算 64k × 64k = 41 亿次相似度，解码时每生成一个 token 都要从 HBM 加载整个 KV cache——内存带宽成了瓶颈。人们用滑动窗口（只看最近 512 个 token）、KV cache 剪枝（推理时丢弃"不重要"的 token）、聚类索引（把相似的 K 聚在一起）等方法缓解，但都卡在同一个问题：这些稀疏模式要么是训练后才引入的（模型没学过怎么用它），要么是启发式的（预设规则不一定对），要么需要动态重组内存布局（GPU 上跑不快）。

关键困境是：**稀疏性、可训练性、硬件效率三者不可兼得**。训练时全程稀疏能学到最优模式，但现有方案要么选择操作不可微（要加辅助损失，效果反而变差），要么内存访问不连续（Tensor Core 用不起来）。论文选的锚点是：既然注意力权重本来就呈块状分布，能不能直接在块级别做选择，让选择本身变成可训练且硬件友好的操作？

## 它真正看见了什么

论文的核心判断是：**稀疏注意力的瓶颈不在"稀疏"而在"不对齐"**——不对齐硬件（内存访问零散）、不对齐训练（选择规则外置）、不对齐天然模式（强制逐 token 选择）。三个承重概念撑起了这个判断：

**块状注意力分布**：论文可视化了一个 27B Full Attention 模型的注意力图，发现相邻的 K 常有相似的注意力分数，呈现块状聚集。这不是"应该"而是"实际"——意味着如果按块选择而不是逐 token 选择，天然模式就不会被破坏。识别标志：注意力图上连续的浅色区域（高权重聚集）。

**三层稀疏结构**：输入序列被切成块，然后三层并行处理：(1) 压缩层：每个块池化成一个代表 token，捕获全局语义；(2) 选择层：用块级索引选出最重要的 n 个块，保留关键细节；(3) 滑动窗口：保留最近 w 个 token，保证局部连贯。三层输出拼接后投影。这个结构的关系是：压缩层提供「在哪找」的语义线索，选择层据此「精确取回」，窗口层保证「最近发生什么」。案例：长文档问答中，压缩层可能捕获「第三段提到关键人物」，选择层取回整个第三段，窗口层保留问题本身。

**GQA 组内共享索引**：GQA（Grouped-Query Attention）把多个查询头共享同一组 K/V。论文让组内所有头共享同一个块选择索引——不同头可以有不同权重，但访问同一组块。关系：共享索引让内存访问连续，组内权重差异保留表达能力。这解决了一个看似矛盾：「稀疏要精准」vs「硬件要整齐」。

```text
┌─────────────────────────────────────────────────────────────┐
│                    输入序列 (长度 s)                        │
│  [t₁ t₂ ... t_l | t_{l+1} ... t_{2l} | ... | t_{s-l} ... t_s] │
└───────────────────────┬─────────────────────────────────────┘
                        │ 分块 (块大小 l=32)
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
  ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ 压缩层   │    │ 选择层   │    │ 滑动窗口 │
  │ 每块池化 │    │ 选 n 块  │    │ 最近 w   │
  │ → 全局   │    │ → 精准   │    │ → 局部   │
  └────┬─────┘    └────┬─────┘    └────┬─────┘
       │               │               │
       └───────────────┼───────────────┘
                       ▼
                ┌──────────────┐
                │  三层拼接    │
                │  + 投影      │
                └──────────────┘
```

**硬件对齐内核**：三个设计让 Triton 内核高效：(1) 块级访问让 K/V 加载连续，Tensor Core 能满载；(2) GQA 共享索引让同一组块只加载一次，多 复用；(3) 循环调度避免重复传输。结果：64k 序列上，前向传播比 FlashAttention-2 快 9.0 倍，反向传播快 6.0 倍。

**原生可训练**：选择层的块索引来自「查询与块代表 key 的相似度」，这个操作在块级别可微（选中的块内部是标准注意力），不需要辅助损失。模型在预训练时就学会了「什么块重要」，而不是推理时临时决定。对比实验：用辅助损失训练的块选择方案训练 loss 更高，启发式无参数方案更差——证明原生训练的价值。

证据与边界：主实验在 27B 参数、260B token 数据上预训练，8 个基准测试中 7 个超过 Full Attention，在多跳问答（+0.087）、代码理解（+0.069）、段落检索（+0.075）等长上下文任务上优势明显。效率上，64k 序列解码加速 11.6 倍，训练加速随序列长度增长（8k: 2.1x, 64k: 9.0x）。链式思维推理实验：用 DeepSeek-R1 蒸馏后，NSA-R 在 AIME 数学题上准确率比 Full Attention-R 高 0.054（16k 上下文）——说明稀疏训练没破坏推理能力，反而因为能学更优模式而更强。边界：论文对比的是「全程稀疏训练」vs「推理时才稀疏」，没证明「稀疏训练后推理再用全注意力」会怎样；效率数据在 A100 上测得，其他硬件架构可能不同。

## 我能带走什么

以后看到「稀疏注意力方法」，我先不急着判断「它能省多少计算」，而会先问两个问题：(1) 它是训练时就开始稀疏，还是推理时才引入？前者让模型学会怎么用，后者是强行压缩。(2) 它的内存访问是块对齐的，还是零散索引？前者 Tensor Core 友好，后者可能跑不满硬件。

真正相关的用法：如果我要做长上下文 LLM，NSA 的三层结构（压缩+选择+窗口）是一个可以直接借鉴的设计；如果我在优化推理速度，GQA 组内共享索引是降低带宽的关键；如果我在设计可训练的稀疏结构，块级选择比逐 token 选择更容易对齐硬件。

# 它没解决脆弱性，只是绕开了它

**副标题**: Learning Transferable Visual Models From Natural Language Supervision（用自然语言监督训练可迁移的视觉模型）

**日期**: 2026-10-20

**来源**: https://arxiv.org/abs/2103.00020

**作者**: Alec Radford, Jong Wook Kim, Chris Hallacy, Aditya Ramesh 等（OpenAI）

**发表场所**: ICML 2021（arXiv 2021-02）

---

## 速读

一张歪斜的手写数字，CLIP 认不出来，输给了"把原始像素摊平直接拟合逻辑回归"这种最笨的基线；同一套权重，看一幅香蕉的简笔画，却把在 ImageNet 上准确率相同的 ResNet-101 甩开一大截。论文没有把这个反差解释成"手写体太难"，它给的机制是：零样本能不能成立，取决于两件事——这个任务能不能被一句话说出来，以及这些概念在四亿对图文里被覆盖过没有。手写数字是"说得出、没见过"，起重机/鹤是"见过、说不清"。顺着这条线，论文还给出了第二个、我认为更值钱的判断：所谓"鲁棒"，很大程度上不是模型的属性，而是"你没让它在这个分布上训练过"的副产品——把 CLIP 在 ImageNet 上适配一遍，同分布准确率涨 9.2 个百分点，七个自然偏移数据集上的平均表现反而略微下降。以后我看到"通用"这个词，会先问一句：它被允许在多少个目标分布上适配过。

## 它到底在解决什么

想象一张手写数字的照片：黑底白字，笔画歪斜，是人随手写的"7"。

CLIP 认不出来。不是差一点，是输给了计算机视觉里最笨的一种办法——把原始像素摊平，直接拟合一个逻辑回归。论文在这里用了一个不太好意思的词，说这条基线"简单得令人尴尬"。

再换一张图：一幅香蕉的简笔画。同一套权重，表现远远好过 ResNet-101，而这两个模型在 ImageNet 验证集上的准确率是一样的。

数字一样，能力剖面完全不同。这就是这篇论文真正要解释的东西：它到底在什么意义上"通用"？

原来的做法是把标签固定下来。一个视觉系统在 ImageNet 上训练，输出就是那一千个类别；想要新类别，就得为新类别再标一批数据、再训一个头。问题不是不够准，是每加一个任务就要重来一次，而"任务"本身没法被枚举完——没人能提前列出世界上所有值得分类的东西。

CLIP 换掉的正是这一步：它不再预测固定的类别，而是判断一段文字和一张图配不配。于是"任务"从一张标注表变成了一句话，换数据集不用重训，只要把类别名写出来。在 ImageNet 上它零样本就到了 76.2%，与原始 ResNet-50 打平，而它一个训练样本都没用过。

可这么一换，旧的理解就缺了一块。旧说法里"通用"是模型的一个属性，用"它能在多少个数据集上表现好"来量。一旦任务是被一句话指定的，"表现好"就同时依赖两件事：这句话说得清不清楚，以及这些概念在训练语料里出现过没有。这两件事都不是模型能力，它们是模型和世界之间的接口条件。我读完的理解是，这篇论文真正的功劳，是把"通用"从一个形容词拆成了这两个可检查的条件；它的代价，也正好藏在这两个条件里。

## 它真正看见了什么

一句话：零样本迁移成立，当且仅当任务说得清、概念见过；而"见过"是按方向算的，往一个方向加，别的方向不会跟着涨。

先把"零样本"这个词的单位校准。在这篇论文之前，零样本学习通常指"识别没见过的类别"——训练时没有猫，测试时要认出猫。CLIP 把它换成了"没见过的数据集"：整个数据集在预训练里不存在，模型只看过类别名。这个替换不只是换了考试科目，它换了考试的性质。前者考的是能不能把学到的属性重新组合成新类；后者考的是能不能照着一句任务说明直接开工。作者自己也知道这里有水分：像 CIFAR-10 这样的数据集，谁也说不清它测的是哪个"真实任务"，在它上面做零样本，测的其实是分布偏移下的稳健性，而不是任务迁移。这句限定是论文自己写的。

那么"照着一句话开工"靠什么？靠标签就是文本。文本编码器读进 "a photo of a dog"，吐出一个向量；这个向量被直接当成一个线性分类器的权重——论文把文本编码器叫作 hypernetwork，意思不是"多任务学习"，也不是"先训一个万能特征再微调一个头"，而是分类头被现场生成出来。三十多个数据集，一个模型，一次都没重训过。

代价立刻出现。ImageNet 里既有吊车也有鹤，英文都是 crane；只有一个光秃秃的词喂进去，模型没有上下文可用。论文的做法是给每个标签套一句模板（"a photo of a {label}."），在 ImageNet 上光这一步就有可测的提升；至于吊车和鹤是否就此分清，论文没有单独验证，它只把多义性列为这类接口的常见麻烦。这不是修辞讲究，是信息量问题：分类器是被这句话生成的，这句话少一个限定，生成出来的分类器就少一个维度。同一条机制在偏见实验里更刺眼——把"儿童"这一个词加进候选标签，二十岁以下被归进犯罪类或非人动物的比例立刻塌下去。标签集不是配置项，它是模型的一部分。

第二个条件：见过。同是细粒度分类，零样本 CLIP 在 Stanford Cars 和 Food101 上反超 ResNet-50 特征上的线性探针一大截，在 Flowers102 和 FGVC Aircraft 上反而落后。任务难度解释不了这个方向差——花的种类并不比车的型号更难分。作者的解释是：WIT 和 ImageNet 里各个任务的监督量不一样。这是推测，论文没有去数每个概念在四亿对里出现过多少次；但它和另一个更干净的例子对得上：手写数字。作者做了最近邻检索，发现预训练语料里几乎找不到像 MNIST 那样的图。所以"覆盖"不是数据总量，是"这个概念的图文对有多密"。四亿对不是均匀铺开的，它在某些概念上极厚，在另一些概念上近乎为零。

两个条件并起来，就是这篇论文的最小模型：任务要被一句话说出（接口条件），概念要在图文对里被覆盖过（数据条件）。第一个决定"能不能问"，第二个决定"答不答得出"。

```text
                概念在图文对里被覆盖过
                     是              否
            ┌────────────────┬────────────────┐
  任务   是 │ 狗、车、食物    │ 手写数字、      │
  说得清    │ 零样本直接可用  │ 估计到车的距离  │
            ├────────────────┼────────────────┤
        否  │ 起重机 / 鹤     │ 论文承认大量    │
            │ 靠模板补限定    │ 存在，未逐个列举│
            └────────────────┴────────────────┘
```

回到那张手写数字。它不是败在笔画太乱，也不是败在模型太小——论文里最大的模型一样不行。它败在"没见过"这一格：这个分布几乎没被四亿对图文覆盖到。而香蕉的简笔画落在"说得出、见过"那一格，所以同一套权重能在那里反超一个准确率相同的 ResNet-101。锚点的两半，是同一行的两个格子。

模型的区别性在邻近情况上更清楚：给它看 ImageNet 的训练集、拟合一个线性分类器，同分布准确率涨了 9.2 个百分点，七个自然偏移数据集上的平均表现却略微下降，ImageNet-R 和 ObjectNet 上还往下掉了。这不符合直觉——涨了 9.2 个点，那是通常要好几年才攒得出来的进步，怎么会一点没换回来？模型给的答案是：适配是在往一个方向加覆盖，它只把那个方向的密度加上去了，别的方向一点没变；而总成绩不是覆盖率的总和，是每个方向各自的表现。论文把"高出那条同分布→偏移经验线多少"叫有效鲁棒性，把"偏移集上绝对准确率涨了多少"叫相对鲁棒性，两个词正好把这件事分开：适配买到了后者，前者没有。

同一个道理也解释了论文里那个更怪的观察：从零样本走到少样本，准确率不升反降。人只看一个样本就跳升一大截，机器给了样本反而更差。因为样本也是一种分布特定的适配，它买来的是这个分布上的密度，代价是把语言里那条更宽的对应关系挤掉。剂量一直加到全监督，鲁棒性的红利就基本消失。论文的归纳是：高有效鲁棒性看起来来自"尽可能少让模型接触分布特定的训练数据"，代价是牺牲该数据集上的专属表现。这句是作者的归纳，不是被证明的定律。

证据的分量要说准。上面这些是在 ImageNet 和那七个自然偏移数据集上测出来的，作者明确写了"我们对这些问题现在没有确信的答案"，还邀请其他实验室在自己的模型上复核。所以"适配会吃掉鲁棒性"目前是一个在这套设置下稳定出现的现象，不是一个普遍机制。另外两处也要打折扣：论文虽然主打零样本，但开发过程中反复在完整验证集上看分数，这不是真的零样本；评测集也是围着 CLIP 的能力凑出来的。至于"是不是把测试集背下来了"，作者做了重叠检测，检测到的重叠很小、几乎不改动任何数据集的总准确率，且大多在统计上不显著——这一点他们查得比多数人认真。还有一条边界是硬的：零样本分类器只能从给定的那组标签里选，它不会说出标签之外的话，这比图像描述模型窄得多；而作者估算，要真正追上当时的 SOTA，还需要多得多的算力，多到现有硬件承担不起。

## 我能带走什么

一条判断规则：以后看到"通用""零样本""鲁棒"这类词，先不急着判断这个模型有多强，先问一句——**它被允许在多少个目标分布上适配过？**

两个真正用得上的地方。看评测时，如果榜单上的类别名是精心挑的、提示词是调过的，那分数里有相当一部分买的是"任务描述的质量"，不是模型能力：论文里光是换提示词并做集成，就拿到了与加大模型规模相当的收益，而这份收益不花训练算力。看产品时，标签集要当接口来设计——加一个词能让一群人从"罪犯"里掉出来，也能让他们掉进去，所以类别设计不是配置项，是产品行为的一部分。

至于这篇论文本身，它没有解决深度学习的脆弱性。它自己说了，它是绕开：赌数据足够大足够杂，以至于一切都算同分布。手写数字证明这个赌很容易被戳破。所以更准确的说法是，它造了一把新尺子，把"通用"从形容词变成了两个可检查的条件；尺子很好用，但它量的不是智能，是覆盖面。

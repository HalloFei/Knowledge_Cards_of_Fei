越靠近算核，越快、越小、越贵

一张 GPU 卡里的内存金字塔 · register / shared / L1 / L2 / HBM / CPU RAM

读推理或训练的系统论文，几乎每篇都在跟“内存”较劲：FlashAttention 要减少 HBM 读写，PagedAttention 说 HBM 被留白浪费，量化要把权重塞得更小。但这些名字谁快谁慢、谁在哪、谁归谁管，很容易糊成一团。理清它们只靠一条物理规律：

存储离计算单元越近 → 越快、越小、越贵；越远 → 越慢、越大、越便宜

四个量分清楚(别混):
· 可见范围 = 谁能访问这块存储(线程私有 / 块内共享 / 全卡共享)
· 延迟 latency = 发出一次读请求,到第一个数据到手,要等多久;单位 cycle(时钟周期)。
· 带宽 bandwidth = 数据一旦开始流,每秒能搬多少字节;单位 TB/s、GB/s。衡量"搬运量",不是"等待时间"。
· 容量 capacity = 能存多少字节,单位 KB / MB / GB。
延迟 ≠ 速度/带宽,这是两个独立的量,不能互相换算。
打比方:延迟像"从下单到第一件货到手的等待时间";带宽像"货运管道每秒能吞吐多少货"。一条通道可以既高延迟(离得远、等很久)又高带宽(一旦通了车流巨大)。HBM 就是典型:发一次请求要等几百 cycle(延迟高),但流起来每秒能搬 2-3 TB(带宽高)。
什么是 per-cycle latency(单周期延迟)?
1 cycle(时钟周期) = GPU 时钟跳一下的时间。GPU 主频约 1-2 GHz,所以 1 cycle ≈ 0.5-1 ns。
· register "延迟 ~1 cycle" = 发出读请求后约 1 拍就拿到数据,几乎零等待、与运算同步。
· HBM "延迟 ~几百 cycle" = 发请求后要干等几百拍数据才回来 —— 这正是 GPU 要靠不停切换 warp 来"填补这段等待"的原因。

一句话记住这条反向张力：
片上寄存器/SRAM 比片外 HBM 大约延迟低200倍、带宽高5倍，但容量小约 1000 倍；
再看CPU RAM，延迟高约1000倍，容量却大上万倍。
→ 越快的越小、越大的越慢，两条曲线几乎精确反向——所有内存优化都在这条张力上做取舍。

② 为什么会分这么多层：材料决定快慢大小

SRAM、DRAM、HBM 常被并排念出来，好像是三种同级的东西。其实它们回答的是三个不同的问题——一块存储可以同时有三个标签。上一节的“快慢大小”，根子就在这里的电路材料。

电路怎么做的？SRAMDRAM

看用什么记住一个比特

  • SRAM：触发器，通电即记，快、贵、占面积
  • DRAM：电容存电荷，需定时刷新，慢、便宜、密

装在哪里？片上 / 片外

看在不在 GPU 硅晶片 (die) 上

  • 片上：register / shared / L1 / L2，都是 SRAM
  • 片外：HBM、CPU RAM，都是 DRAM

怎么封装的？HBM

看 DRAM 用什么形态接上来

  • HBM＝3D 堆叠、贴着 GPU 的高带宽 DRAM
  • 所以「显存」＝HBM＝一种封装讲究的 DRAM
深入一层：SRAM 和 DRAM 到底长什么样、差在哪？

一句话：SRAM/DRAM 说电路，片上/片外 说位置，HBM 说封装。HBM 不与 SRAM 并列，它本质仍是 DRAM。

RAM 和 memory 的差别：memory（内存/存储）是统称，register、shared memory、L1/L2、HBM、CPU RAM 都属于 memory；RAM（Random Access Memory，随机存取存储器）是 memory 的一个子集，广义上指“可按地址随机访问”的易失性存储器，SRAM 和 DRAM 都属于 RAM；换句话说，RAM ⊂ memory。但口语/产品语境里说“内存/RAM”时，通常特指 CPU 主存（DRAM）。GPU 的 register、shared memory、L2、HBM 也都是 memory，只是不一定叫 RAM。为避免混淆，本文里统一把 block 内共享的 SRAM 叫作 shared memory。

③ L1、L2、shared 到底是什么

前面按“电路材料”把存储分成了 SRAM 和 DRAM。但你在文档里更常看到的是 L1 / L2 / shared memory 这些名字——它们不是第三种电路，而是同一种 SRAM 按“离算核远近 / 共享范围”排成的缓存层级。

· L1（一级缓存）＝每个 SM 私有、离计算单元最近的一小块 SRAM，最快、最小（和 shared memory 是同一块物理 SRAM 的两种用法）。
· L2（二级缓存）＝全芯片所有 SM 共享的一块较大 SRAM，比 L1 慢些、大些，是访问片外 HBM 前的最后一道片上缓冲。
· shared memory＝程序员能手动管理的那块 L1 SRAM，一个 block 内的线程共用。

“L1 比 L2 快” 是因为它更小、更近；缓存的通用规律就是越近越快越小。另：GPU 一般没有独立 L3（那是 CPU 的层级），到 L2 就直连 HBM。

④ 执行层次 ↔ 内存层次：先分清“软件逻辑层”和“硬件物理层”

先分清两个架构：CUDA 的 grid / block / warp / thread 是软件逻辑层；SM、寄存器堆、shared memory / L1、执行单元是硬件物理层。两者通过“调度 + 资源分配”映射，不是“硬件盒子套盒子”的物理包含关系。下面这张图说的是“逻辑执行单位的存储可见范围”，不是“block 是 SM 里焊死的一个子部件”。

存储的“可见范围”不是随便定的，而是由谁在执行决定的。CUDA 的逻辑执行单位与内存层次严格对应：

软件逻辑层（执行模型）
grid → block → warp → thread
这些是“任务 / 执行上下文”，不是芯片上的独立零件。
硬件物理层（执行资源）
GPU → SM → 寄存器堆 / shared memory / Tensor Core / 执行单元
这些是真正焊在芯片上的物理资源。
映射不是包含：block 不是 SM 的固定子部件；它是被调度到 SM 上执行的任务。block 的 shared memory 来自该 SM 的物理 shared memory 配额，block 结束后归还。warp 是 SM 的指令调度粒度，thread 是逻辑执行上下文。
thread 线程逻辑执行上下文；真正物理的是 SM 里的执行单元
↔

occupancy 就是一道除法题

寄存器格子总数是固定的（硬件焊死，如 A100 每 SM 有 65536 个）；一个线程占几个格子是可变的（代码越复杂占越多）。两者一除，决定能同时跑多少线程：

每线程用 32 个 → 65536 / 32 = 2048 线程同时住下 （车间满，快）
每线程用 128 个 → 65536 / 128 = 512 线程 （车间空大半，慢）

线程占得越多 → 分母越大 → 同时驻留的 warp 越少 → GPU 靠“切换 warp”隐藏延迟的本钱变少。这就是“省着用寄存器”能提速的原因；用超了则寄存器溢出到片外，断崖式变慢。

⑤ 回到锚点：FlashAttention vs PagedAttention

两者都在跟内存较劲，但优化的不是同一层、不是同一件事，因此可以叠加使用。

FlashAttention · 省带宽

战场在 HBM ↔ SRAM 的搬运（跨层）

HBM ──搬一块──▶ SRAM
       算完再搬下一块
◀── 少读少写 ──

不落地中间大矩阵，减少 HBM 往返次数。

PagedAttention · 省容量

战场在 HBM 内部的排布（层内）

HBM: [页][页][页]…
  像内存分页，按需分配
  不给每个序列预留一大段

消除 KV Cache 的内部留白，装下更多并发序列。

读任何内存优化论文，先问两句：它在搬哪两层数据（省带宽）？还是在省哪一层的占用（省容量）？

我能带走什么

  • 用一条轴统一所有名词：离算核的物理距离 → 决定快慢、大小、贵贱。
  • 三套标签别混：SRAM/DRAM（电路）、片上/片外（位置）、HBM（封装）；HBM 本质是片外 DRAM。
  • 分清软件逻辑层（grid/block/warp/thread）与硬件物理层（SM/寄存器堆/shared memory/执行单元）；存储的可见范围由逻辑执行单位决定，但物理资源都在硬件层：thread 的上下文存在寄存器堆、block 被调度到 SM 后分到物理 shared memory 配额、全卡共享 L2/HBM。
  • 看优化论文先分类：省带宽（跨层搬运，如 FlashAttention） 还是 省容量（层内排布，如 PagedAttention）。

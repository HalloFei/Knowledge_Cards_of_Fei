## 速读

读推理或训练的系统论文,几乎每篇都在跟"内存"较劲:FlashAttention 说要减少 HBM 读写,PagedAttention 说 HBM 被留白浪费,量化说要把权重塞进更小的空间。但"HBM""SRAM""L2""shared memory"这些词到底谁快谁慢、谁在哪、谁归谁管,很容易糊成一团。理清它们其实只靠一条物理规律:**存储离计算单元越近,就越快、越小、越贵;越远就越慢、越大、越便宜。** 于是一张 GPU 卡里的内存自然长成一座金字塔——顶端是刻在硅片上、每个线程私有的寄存器(register),快到以时钟周期计但只有几十 KB;往下是一个线程块共享的 shared memory 和 L1、再到全芯片共享的 L2,都还在片上、都是 SRAM;跌下芯片边界就是 HBM(也就是"显存",本质是一种高带宽封装的 DRAM),几十 GB 但慢一个数量级;最外层是主板上的 CPU RAM,只在换出兜底时才用。搞懂这座金字塔后,再看任何"内存优化"论文,第一件事就能定位:它在搬哪两层之间的数据,还是在省哪一层的占用?

## 它到底在解决什么

一个具体困惑:为什么同样叫"内存",FlashAttention 拼命想把数据从 HBM 挪进 SRAM,而 PagedAttention 却在 HBM 内部斤斤计较排布?它们说的明明都是"GPU 内存",为什么优化方向像在两个世界?

要解开,得先承认一件反直觉的事:**GPU 上不存在单一的"内存",而是一整套速度、容量、可见范围都不同的存储层,各有各的物理位置和归属。** 把它们当成一块统一的东西,就永远分不清一篇论文到底在优化什么。

麻烦还在于这些名字混用了分类维度:register / shared memory / L1 / L2 是**按"在片上的角色"**分的;SRAM / DRAM 是**按"用什么电路存 1 bit"**分的;HBM 又是**按"怎么封装"**分的。三套维度交叉,才让人觉得"SRAM、HBM、L2、显存"像四个并列的东西——其实它们分属不同的问题。

所以真正要解决的问题是:**把这些名字各归各位,拼出一张"谁在哪层、多快、多大、谁能看见"的完整地图。**

## 它真正看见了什么

一句话:**只要抓住"离算核的物理距离"这一根轴,所有名字都能排进同一座金字塔;而 SRAM/DRAM、片上/片外、L1/L2 只是从不同角度描述同一座塔的不同楼层。**

先补两个最容易混的分类维度,后面所有楼层都靠它们定位:

**片上(on-chip)对片外(off-chip)**,区分的是"在不在 GPU 那块硅晶片(die)上"。片上数据走芯片内部极短的金属连线,快且省电,但硅片面积极贵,只能做很小容量;片外是芯片之外独立的存储颗粒,要"出芯片走一段路",慢但能堆大容量。这是金字塔最硬的一道分界线。

**SRAM 对 DRAM**,区分的是"用什么电路存1 bit"。SRAM 用两个反相器首尾相扣(约 6 个晶体管)——它们互相"撑住"对方的状态,只要通着电就自锁不变,所以叫 Static(静态)、不需刷新,快、贵、密度低;DRAM 用"1 电容 + 1 晶体管",靠电容里存不存电荷来表示 1/0,但电容会慢慢漏电(几十毫秒就漏光),必须每隔几毫秒把每一位读出再写回,这个动作就叫**刷新(refresh)**,Dynamic(动态)正指这个不停刷新的过程;它慢些但一个比特只占 1 电容+1 管,又小又便宜、密度高。**关键:片上的高速存储几乎都是 SRAM,片外的大容量显存是 DRAM。** 而 **HBM 不是第三种电路,它就是 DRAM**——只是把多层 DRAM 芯片 3D 堆叠、用极宽总线紧贴 GPU 封装,换来高带宽。

有了这两把尺子,从塔尖往下逐层落位:

**寄存器(register)** 是塔尖。要先分清两件事:一是**寄存器文件(register file)**——每个 SM 上一大堆**数量固定**的小格子(如 A100 每个 SM 有 65536 个 32 位寄存器,这个数硬件焊死、不会变);二是**一个线程要占几个格子是可变的**,由代码复杂度决定,简单 kernel 一个线程用二三十个,复杂的用上百个。线程私有——每个线程只看得见自己那几个格子,直接喂给计算单元的操作数就住在这儿,速度以单个时钟周期计,是全塔最快的。用超了会"寄存器溢出",数据被踢到慢得多的地方,性能骤降。它是 SRAM、片上。**记住这对关系:格子总数固定(供给),线程占用量可变(需求)——这正是下面 occupancy 的根源。**

**shared memory(共享内存)** 往下一层。它由**同一个线程块(block)内的线程共享**,是程序员能显式管理的一块高速暂存区——把要反复用的数据从 HBM 搬进来放这儿,块内线程就能高速反复读,这正是 FlashAttention 之类算子的核心手法。它同样是片上 SRAM,速度接近 register,容量在每块几十到上百 KB 级。

**L1 cache** 和 shared memory 在物理上往往是**同一块片上 SRAM**,只是一个由硬件自动缓存、一个由程序员手动掌控——很多 GPU 上二者共用一块存储、可配置划分比例。作用范围也是单个线程块/SM 级。

**L2 cache** 再往下:它是**整块 GPU 芯片上所有计算单元(SM)共享**的一层缓存,容量比 L1 大得多(MB 到几十 MB 级),但因为要服务全芯片、物理距离更远,比 L1 慢。它是所有 SM 访问 HBM 时的公共中转站——数据从 HBM 上来,先过 L2。它仍是片上 SRAM。

(**L3 在 GPU 上一般不作为独立层出现**。CPU 常有 L1/L2/L3 三级缓存;GPU 的缓存体系通常止于 L2,再往下就直接是 HBM 了。所以谈 GPU 时说"L3"多半是从 CPU 类比过来的,实机上没有对应层——这点值得记下,免得张冠李戴。)

**跌出芯片边界,就是 HBM(显存)**。它是片外的 DRAM,容量一跃到几十 GB(A100 有 40/80GB),但带宽和延迟比片上 SRAM 差一个数量级。模型权重、KV cache、激活值这些"大块头"都住这儿。

**最外层是 CPU RAM(host memory)**,在主板上、经 PCIe 或 NVLink 与 GPU 相连,容量最大但对 GPU 而言最慢,通常只在显存装不下、需要换出(swap)兜底时才动用。

把整座塔画出来(容量/带宽为 A100 量级近似):

```text
        计算单元 (SM: CUDA cores / Tensor cores)
   ┌──────────────────────────────────────────────┐
片 │ register      线程私有   ~1 cycle    数十KB/块  │ SRAM
上 │ shared/L1     块内共享   ~20-30 cyc  ~百KB/SM   │ SRAM
   │ L2            全芯片共享 ~200 cyc    MB~数十MB  │ SRAM
   └──────────────── 芯片(die)边界 ──────────────────┘
片 │ HBM(=显存)   全卡可见   ~300-600cyc 40/80 GB   │ DRAM
外 │ CPU RAM       主机       ~数千 cycle 数十~百GB  │ DRAM
   └──────────────────────────────────────────────┘
       越往下: 越慢 越大 越便宜 越远离算核
```

**把这条张力换成明确的倍数感受**(以片上寄存器/SRAM 为基准,A100 量级近似):

- **延迟**:register ~1 cycle 是基准;L2 ~200 cycle(**慢约 200 倍**);HBM ~300-600 cycle(**慢约 300-600 倍**);CPU RAM ~数千 cycle(**慢 1000 倍以上**)。
- **带宽**:片上 >10 TB/s 是最高档;HBM 2-3 TB/s(约为片上的 1/4-1/5);CPU RAM 只有 10-100 GB/s(**比片上慢约 100-1000 倍**)。
- **容量**:片上 SRAM 合计才 ~40 MB;HBM 有 40-80 GB(**大约 1000-2000 倍**);CPU RAM 100 GB-1 TB(**大约几千到上万倍**)。

一句话:**越快的越小、越大的越慢,两条曲线几乎精确反向**——寄存器比 HBM 快几百倍,但容量小约 1000 倍;HBM 又比 CPU RAM 快上千倍,但容量小上百倍。所有内存优化,本质都是在这条"快↔大"反向张力上做取舍。

**回到原锚点**——FlashAttention 与 PagedAttention 为什么像在两个世界?现在能一句话说清:**它们作用在金字塔的不同楼层。** FlashAttention 优化的是"**HBM ↔ shared memory/SRAM 之间的搬运**":把注意力计算分块,让数据尽量留在片上高速区反复用,少来回读写 HBM——省的是**带宽**。PagedAttention 优化的是"**HBM 这一层内部怎么排布才不浪费**":用分页避免为最大长度预留连续显存——省的是**容量**。一个在跨越芯片边界的那道窄门上做文章,一个在片外那层的占用上做文章,自然互不冲突、可以叠加。

**区分一个邻近情况**:L1 和 shared memory 常被当成两回事,但在多数 GPU 上它们是**同一块物理 SRAM**的两种用法——L1 硬件自动管、shared memory 程序员手动管。所以"增大 shared memory"往往意味着"L1 可用空间变小",这是配置上的此消彼长,不是两块独立存储。认不出这点,就会误以为能同时把两者都调到最大。

**内存层次还有一面镜子:执行层次。** 上面反复出现的"线程""线程块""SM",其实和内存层次是同一件事的两面,严格对应——搞懂这层对应,就明白"谁私有、谁共享"不是硬记的,而是由"谁在用它"决定的。

先把四级执行单位说清:

- **线程(thread)** 是 GPU 上最小的执行单位。一个线程跑一份相同代码、只处理自己那一小份数据。它的私有存储就是 register。
- **线程束(warp)** 是硬件真正调度的单位:**32 个连续线程被捆成一个 warp,锁步执行同一条指令**(称 SIMT——同一指令、多个线程)。你写代码看到的是"一个线程",但硬件一次调度的最小活动单位是"一个 warp = 32 线程"。这一层没有自己独立的存储,它是"register 这层存储"和"调度/occupancy"之间的桥梁。
- **线程块(thread block)** 是一组线程(即若干个 warp)打包成的团队。块内线程能协作——共享同一块 shared memory,还能互相同步等待。它是"能一起干活"的最小单位。
- **SM(Streaming Multiprocessor,流多处理器)** 是 GPU 芯片上一个物理的计算引擎,一块 GPU 有几十到上百个。**线程块被调度到某个 SM 上执行**;L1/shared memory 是每个 SM 私有的,而 L2 由所有 SM 共享。

于是执行层次和内存层次一一对应:

```text
执行单位                 对应的私有/共享存储
thread    ───────────    register       (线程私有)
 └ warp(32线程锁步)       (整束的 register 须同时驻留在 SM 上)
block     ───────────    shared / L1     (块内共享, 落在某个 SM 上)
所有 SM   ───────────    L2 / HBM        (全卡共享)
```

这解释了前面那句"register 线程私有、shared memory 块内共享、L2 全芯片共享"到底从何而来:**存储的可见范围,就是由使用它的那层执行单位决定的**——线程私有的东西别的线程看不见,块共享的东西出了这个块也看不见。

**改变一个条件**:如果一个 kernel 用的寄存器过多会怎样?这里 warp 是关键的计数单位——**一个 warp 要能运行,它那 32 个线程各自要的寄存器必须全部同时驻留在 SM 的寄存器文件里**。而寄存器文件的格子总数是固定的(如 A100 每 SM 有 65536 个寄存器),线程占用量却是可变的,于是 occupancy 本质是一道**除法题**:

```text
能同时驻留的线程数 = 固定的寄存器总数 ÷ 每个线程占用的寄存器数
  每线程用 32 个  → 65536 / 32  = 2048 线程同时住下(occupancy 高,车间满)
  每线程用 128 个 → 65536 / 128 =  512 线程(occupancy 低,车间空大半)
```

线程占得越多 → 分母越大 → 能同时驻留的 warp 越少 → 靠切换 warp 来隐藏内存延迟的能力变弱;严重时寄存器溢出到片外,速度断崖式下跌。这从反面印证金字塔的因果:**塔尖格子总数是死的,省着用(每线程少占)才能让 SM 驻留更多 warp、喂饱并行。**

## 我能带走什么

> 以后读任何"内存优化"的 GPU 论文,我先不急着记它的技巧,而先定位:**它在搬哪两层之间的数据(省带宽),还是在省哪一层的占用(省容量)?**

这个定位问题几乎能拆开所有相关工作:FlashAttention/算子融合动的是"HBM↔片上 SRAM 的搬运量";PagedAttention/KV cache 管理动的是"HBM 内部的占用效率";量化/权重压缩动的是"让大块头在 HBM 里更小";offloading/换出动的是"HBM↔CPU RAM 那道最慢的门"。识别信号很简单——看它反复念叨的是"带宽/搬运次数",还是"容量/占用/碎片"。前者在跨层搬运上做文章,后者在某一层内部做文章。抓住这条,再多的新名词都能挂回这座金字塔。

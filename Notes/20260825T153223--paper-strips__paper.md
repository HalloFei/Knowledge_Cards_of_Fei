# 把"证明目标"改成"改造世界"，Agent 才走得动

**副标题**: STRIPS: A New Approach to the Application of Theorem Proving to Problem Solving

**日期**: 2026-08-25

**来源**: https://ai.stanford.edu/~nilsson/OnlinePubs-Nils/PublishedPapers/strips.pdf

**作者**: Richard E. Fikes, Nils J. Nilsson

**发表场所**: Artificial Intelligence 2 (1971), 189–208；2nd IJCAI, London, 1971

---

## 速读

一个机器人要"把三个箱子推到一起"，用纯定理证明的做法（Green 1969）连这道题都解不下来：把"世界随每一步动作发生的变化"塞进一阶谓词逻辑，会陷进 frame problem，公理和推导迅速爆炸。STRIPS 的关键动作，是把"回答一个世界里的问题"和"从一个世界走到另一个世界"两件事分开——前者交给定理证明器（只在单个世界模型内工作），后者交给 means-ends 分析（用 add/delete 列表在世界模型之间跳）。于是原来靠证明推不动的东西，被拆成"当前世界 → 差异 → 相关算子 → 前提子目标 → 新世界"的链条。以后再看到 agent 卡住，先别问"它推理不够强吗"，而先问：它有没有一个可以被显式改造的世界模型，以及每个动作有没有说清"我加什么、我删什么"。

## 它到底在解决什么

把机器人放进一个有走廊和四个房间的地图里，让它"推三个箱子到一起"，或者"爬上箱子、把箱子推到灯开关下、打开灯"。这类问题的锚点是：动作会**改变世界**——机器人从 a 走到 b 之后，ATR(a) 就不再成立；箱子从 m 被推到 n 之后，AT(k, m) 变成 AT(k, n)。锚点不是"推理难"，而是"每走一步，之前证明用过的前提就可能失效"。

在 STRIPS 之前，Green 的做法是把整个问题一次性交给一阶谓词演算的定理证明器：把每个动作也写成公理（如 "如果在时刻 t robot 在 a，执行 goto(a,b) 后，在时刻 t+1 robot 在 b"），让证明器从初始状态一路推到目标状态，把动作序列作为证明的副产品抽出来。这条路在小例子里能走通，一旦动作数增加就崩：为了不让证明器错误地保留旧事实，你得为**每个动作**显式写"其他所有事实在这一步保持不变"——这就是 frame problem。论文原文说，Green 的证明器连 STRIPS 里 3-Boxes 这道题的完整版本都解不出来，只能解一个两步动作的简化版。

问题的真正形状因此浮现出来：定理证明擅长"在一个静止世界里回答问题"，但不擅长"跨越很多世界描述一条动作路径"。若不做区分，证明器就会同时承担这两件事，然后被后者拖垮。读者到这里应该开始期待：能不能让"回答问题"和"改造世界"用两种不同的机制？

## 它真正看见了什么

STRIPS 的新判断是：**把世界模型当成可以被算子显式增删的一等对象，而定理证明只在单个世界模型的内部使用**。这一句话里有几个原本没被区分的承重概念，得先长出来，模型才能运转。

**世界模型**。它不是"当前状态的一个符号"，而是一组一阶谓词演算的合式公式（wff）的集合，比如 `AT(BOX1, a)`、`ATROBOT(e)`、`INROOM(ROBOT, ROOM1)`。它区分于"游戏的棋盘状态"这种简单结构：一个机器人世界模型可能有上百条 wff，涵盖房间、门、可推性、位置。它的可观察标志是——你可以对它发起证明查询，比如问"目标 `AT(BOX1,x) ∧ AT(BOX2,x) ∧ AT(BOX3,x)` 是否成立"。

**算子（operator）与算子 schema**。算子不是动作本身；动作是机器人真的执行的例程（action routine）。算子是**用来规划**的抽象对象，只在"找出一串动作"这个阶段被"应用到世界模型上"。每个算子由三部分定义：前提（precondition，一个 wff schema）、删除列表（delete list，动作后不再成立的公式）、添加列表（add list，动作后新成立的公式）。schema 里带参数（如 `push(k,m,n)`），要在应用时用常量替换掉。这三段结构是 STRIPS 最原创的一步——它把"世界怎么变"用一个**局部改写**规则说清楚，而不用去写"其他一切保持不变"。这就是它绕开 frame problem 的具体机制。

**差异（difference）与相关算子（relevant operator）**。这两个概念从 GPS 借来，但被重新连接了。STRIPS 想证明目标 `G` 从当前世界 `M` 成立；若证不出，那次失败的证明本身（未闭合的子句集）就被拿来当作"当前世界和目标之间的差异"。然后 STRIPS 拿这堆残余子句去对比每个算子的 add list：如果某个算子的 add list 能把差异里的子句"消掉"（resolve away），它就被判为"相关"——也就是说，若能达到它的前提并执行它，证明就能继续。这里的"相关"不是模糊的启发式，是有具体判据的：证明器能不能用这个算子的 add list 产生新的 resolvent。

把这几个概念接起来，就得到 STRIPS 的最小解释模型：

```text
当前世界 M + 目标 G
       │
       ▼
定理证明器在 M 内证 G  ──成功──> 完成
       │不成功
       ▼
残余未闭合子句 = 差异 D
       │
       ▼
扫描算子 add list 与 D 匹配 ──> 得到相关算子 O(p)
       │
       ▼
以 O 的前提 G' 为新子目标，把 (M, [G', G]) 推进
       │
       ▼
若 G' 在 M 中成立，把 O 应用到 M：
   新 M' = (M − delete_list) ∪ add_list
       │
       ▼
回到顶部，用 M' 继续证 G
```

这个模型解释了原锚点为什么走得动：3-Boxes 问题里，目标 `∃x. AT(BOX1,x) ∧ AT(BOX2,x) ∧ AT(BOX3,x)` 在初始世界里证不出来，残余的差异包含 `¬AT(BOX2, x)` 一类子句；`push(k,m,n)` 的 add list 里有 `AT(k,n)`，一 match 就产生相关实例 `push(BOX2, m, b)`；它的前提 `AT(BOX2,m) ∧ ATR(m)` 变成子目标，又触发 `goto(m,c)`。就这样，每一步只关心"当前世界的 delta"，从未去证明"其他事实保持不变"。

模型对**邻近情况**的预测也很清楚：如果一个动作的 delete list 写漏了（例如 `goto` 没删掉 `FACING(s)`），下一步 STRIPS 就可能在新世界里错误地使用一条早已过时的事实，规划会得到一个执行不了的计划。论文里为此专门讨论了两个补丁：一是允许 delete list 用变量 schema（`FACING($)` 删所有朝向事实）；二是把非原子谓词（如 `NEXTTO(B1,B2)`) 挂到它依赖的原子谓词（`AT(B1,a)` 和 `AT(B2,a+Δ)`）上，只要底层被删，派生事实自动失效。这两条不是花边，是让局部改写这个假设在含派生事实的世界里仍然成立的**边界条件**。

对**条件变化**的预测：如果算子库不够大或者前提写得太松，"相关算子"这一步会匹配出大量候选，搜索树炸开——论文用一个 evaluation function（剩余子目标数、差异复杂度）来挑节点，但承认这本质仍是 depth-first 主导，"关灯"任务因此拿到的是能跑但非最优的解。这条边界很关键：STRIPS 的效率来自"世界改写局部化"，不来自"搜索够聪明"。

证据方面，论文给了三道任务的实际运行数据（Table 2）：关灯 113 秒/21 个节点/6 步解、推三箱 66 秒/9 个节点/4 步解、跨房间走 123 秒/12 个节点/5 步解——搜索树几乎就等于解路径，说明"从差异反推相关算子"这个启发式在这类任务里把搜索空间压得很紧。这些数字最多说明**这种规划范式在小规模机器人任务上可行**，尚未说明它在有几十上百个算子、需要迭代或条件分支的任务里还能这么直。

## 我能带走什么

以后看到某个 agent 系统卡在"多步任务规划不动"，先不急着判断"它模型能力不够"或"上下文太短"，而先问：**它到底有没有一个可以被显式改造的世界模型？每个可执行动作，有没有明确说清"我需要什么前提、我加什么事实、我删什么事实"？**

这一问会照亮当前 agent workflow 的骨架。ReAct 类 agent 把"世界"塞进 prompt 里的自由文本，"工具调用"的效果只在自然语言观测里体现，等于没有 delete list——上一步的过时信息会一直挂在上下文里干扰后续判断；这是 frame problem 在 LLM 时代的翻版。反过来看，那些工作得比较稳的 agent 框架（LangGraph 的 state schema、BabyAGI 的 task list、OS-agent 的屏幕状态快照、function-calling 里显式的返回值 diff），本质都在做一件事：把世界模型从 prompt 文本里抽出来，让它可以被结构化地增删。这正是 STRIPS 五十年前就点出的分离——**用什么机制"回答当前状态的问题"，和用什么机制"从一个状态走到下一个状态"，必须分开**。

具体两个用法：一是评估一个 agent 系统时，先画它的"world model + operator 表"；画不出来的系统，多半只能做单步问答，做不了长程规划。二是设计工具接口时，除了写"输入/输出"，再补一条"这个工具执行后，agent 的世界模型里什么事实变了、什么事实作废了"——这就是给 LLM 一个可用的 delete list，让它不至于在下一步继续基于过时信息推理。

## 它没解决什么，以及 50 年后仍然难的地方

STRIPS 的"分离 + 局部改写"是一个漂亮的**假设**，而不是一个免费午餐。它把 frame problem 从"每步都要证明其他事实不变"降级为"人工写好 add/delete list"，但这条降级路径本身有几层脆弱假设——正好构成它的适用边界，也正好是 agent 领域至今仍在原地打转的地方。

**一、动作是确定性的、瞬时的、原子的。** 论文里 `push(k,m,n)` 执行后 `AT(k,n)` 一定成立，不会失败、不会中途被打断、不会有副作用溢出到没列进 add/delete list 的事实上。真实机器人（和真实 API 调用、真实浏览器操作）都不是这样：动作会失败、会部分成功、会有延迟、会有并发状态改变。STRIPS 之后的 PDDL 家族（probabilistic PDDL、PDDL+ 加时间与连续变量）都在往这条裂缝里塞补丁，但至今没有一个既能表达真实世界不确定性、又能被高效规划的形式。LLM agent 表现出的"工具调用返回 success，但世界实际没变"就是这个洞的当代版本。

**二、世界模型的"完备性"要人工保证。** 论文用 primitive predicate 的约定把派生事实的失效问题挡住，但前提是**你能把这个世界的原子谓词穷举出来**。房间-箱子-灯这种玩具环境可以，一旦进入开放世界（网页、代码库、真实办公室），"哪些事实是原子的、哪些谓词需要被建模"本身就没有答案。这就是所谓的 **qualification problem**（哪些前提该写进 precondition）和 **ramification problem**（一个动作真正的间接后果有多远），二者都是 frame problem 的孪生兄弟，STRIPS 只处理了最正面那一个。今天 LLM agent 之所以在"帮我订机票"这种任务上翻车，很大程度上是因为没人能把"订机票"背后应该失效的世界事实（信用卡余额、日程、行李配额、伴侣的偏好）显式列出来。

**三、目标是可以用一阶谓词 wff 静态陈述的。** `AT(BOX1,x) ∧ AT(BOX2,x) ∧ AT(BOX3,x)` 是个漂亮目标，但"帮我写一份能说服评审的项目申请"、"让这段代码更 Pythonic"这类目标没法这样写。STRIPS 之后的整个"规划语言 vs 现实目标"鸿沟从未真正被填上——PDDL 越写越复杂，但真实用户从不用它下达任务。LLM 的价值恰恰在于把自然语言目标翻译成某种可执行结构，但**翻译出来的中间表示是否满足 STRIPS 那种"可被局部改写检验"的性质，目前是没有的**——这也是 LLM agent 长程任务里最容易走偏的一步。

**四、规划和执行是分开的，且规划期间世界不变。** STRIPS 假设你先算完整个 operator 序列、再交给执行器执行；执行期间世界不会被别人改动。真实 agent 的世界里，网页会跳版、文件会被别的进程改、其他用户会插入操作——这就要求 replanning、interleaved planning-execution、reactive control，这些方向从 1980s 的 SIPE、PRODIGY 一直做到今天的 hierarchical agent，仍没有一个被普遍接受的答案。

**五、没有学习，operator 库是外生的。** 论文最后一节承认这一点，并把"让 STRIPS 自己学出新 operator"列为未来工作。50 年后我们有了 LLM，它确实能"读文档-生成新工具"，但生成出来的工具是否具备正确的 precondition/add/delete 语义、能否被下游规划器可靠使用，本质上没有验证机制——这就是当前 tool-learning 研究的核心难点。

**六、搜索启发式仍是靠猜的。** 论文自陈 evaluation function 是"剩余子目标数 + 差异复杂度"这类手工特征，因此"关灯"任务只能拿到非最优解。经典规划社区后来发展出 delete-relaxation heuristic（h+、hFF、LM-cut）等一系列理论上有保证的启发式，但都建立在 STRIPS/PDDL 的**离散、确定、完全可观测**假设上；一旦松开这些假设，启发式的保证就丢了。LLM 作为"启发式生成器"是当前的一条新路，但它给出的相关性判断没有形式保证，只是概率上有用。

**给读者的一句话总结**：STRIPS 值钱不是因为它解决了规划，而是因为它把"规划到底难在哪"讲清楚了——难在"世界怎么变"这件事得被显式表达，而不是被寄希望于一个更聪明的推理器自动搞定。50 年过去，LLM 让"推理器变聪明"这条路重新有了希望，但"世界怎么变"这半边至今没被 LLM 吃掉。谁能把这两半重新缝起来，谁就能真正推进 agent。
